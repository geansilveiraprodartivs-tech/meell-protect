==================================================
1. CORRIGIR A VERSÃO PROTEGIDA DAS IMAGENS
==================================================

PROBLEMAS ATUAIS:

1. Algumas imagens, especialmente PNG, estão saindo visualmente corrompidas após gerar a “Versão Protegida”, apresentando faixas, blocos, pixels deslocados ou alterações graves.

2. Arquivos WEBP mantêm boa qualidade, porém aparentemente estão sendo baixados sem receber proteção/fingerprint real.

CORREÇÃO:

- Revise a Edge Function creator-download e qualquer função responsável por gerar a Versão Protegida.
- NÃO aplique fingerprint modificando diretamente bytes brutos/comprimidos de PNG, JPG, JPEG ou WEBP.
- A imagem deve ser corretamente decodificada para pixels, processada e depois recodificada.
- Utilize processamento adequado, como Sharp, quando compatível com o ambiente atual.

Adicionar suporte real para:

- PNG
- JPG/JPEG
- WEBP

A imagem protegida deve preservar:

- aparência visual;
- dimensões;
- orientação;
- transparência quando aplicável;
- proporção;
- qualidade o mais próximo possível do original.

PNG não pode sair corrompido.
WEBP deve receber proteção real.
JPG/JPEG também deve funcionar corretamente.

==================================================
2. PROTEÇÃO EM CAMADA DUPLA
==================================================

Quero manter e aprimorar a Proteção em Camada Dupla.

CAMADA 1 — IDENTIFICAÇÃO DO ARQUIVO

Cada arquivo protegido deve possuir uma identificação única e persistente relacionada ao:

- proprietário/criador;
- protected_file_id;
- copy_id;
- delivery_id quando existir;
- destinatário autorizado quando existir.

Use fingerprint invisível ou técnica equivalente compatível com cada formato.

Não aplique a proteção diretamente nos bytes comprimidos de forma que possa corromper o arquivo.

CAMADA 2 — REGISTRO E RASTREABILIDADE

Registrar no banco a relação entre:

arquivo original
→ cópia protegida
→ proprietário
→ destinatário
→ entrega
→ eventos relacionados.

A função “Verificar Arquivo” deve conseguir consultar esses registros e identificar corretamente a origem da cópia quando a proteção estiver presente.

==================================================
3. CÓPIA IDÊNTICA X VERSÃO PROTEGIDA
==================================================

Manter claramente dois downloads diferentes.

CÓPIA IDÊNTICA:

Deve continuar sendo exatamente o arquivo original.

Não adicionar:

- fingerprint;
- marca d’água;
- alteração de pixels;
- metadata de proteção;
- nenhuma modificação.

VERSÃO PROTEGIDA:

Deve obrigatoriamente passar pelo mecanismo de proteção antes do download.

Nunca retornar silenciosamente o arquivo original quando o usuário escolher “Versão Protegida”.

Se um formato não puder ser protegido, mostrar erro claro em vez de entregar uma falsa “Versão Protegida”.

6. NÃO FINGIR RASTREAMENTO FORA DA PLATAFORMA
==================================================

IMPORTANTE:

Não implemente alegações falsas de rastreamento.

O sistema NÃO deve afirmar que consegue descobrir automaticamente quem enviou um arquivo por:

- WhatsApp;
- Telegram;
- e-mail externo;
- Bluetooth;
- pendrive;
- Google Drive externo;
- redes sociais;
- outros meios fora do controle do Meell Protect.

Se alguém simplesmente baixar o arquivo e enviar a cópia externamente, o Meell Protect pode identificar a origem da cópia através do fingerprint, caso ele sobreviva, mas não pode saber automaticamente quem realizou aquele compartilhamento externo, para quem enviou, nem a data/hora exata sem existir um evento registrado pela plataforma.

Portanto:

Para registrar com precisão:
QUEM COMPARTILHOU + PARA QUEM + DATA + HORÁRIO

o compartilhamento deve acontecer através de um fluxo controlado pelo Meell Protect.

7. CRIAR FUNÇÃO “COMPARTILHAR COM PROTEÇÃO”
==================================================

Criar ou adaptar um fluxo seguro chamado:

“Compartilhar com proteção”

Quando um destinatário autorizado quiser compartilhar o arquivo com outra pessoa:

1. Ele informa o novo destinatário.

2. O sistema identifica automaticamente quem está fazendo o compartilhamento.

3. Cria uma nova entrega vinculada à anterior.

4. Gera uma NOVA cópia protegida exclusiva para o novo destinatário.

5. Essa nova cópia deve possuir um novo copy_id/fingerprint.

6. Registrar a relação:

parent_copy_id
→ child_copy_id

e:

shared_by
→ shared_with

7. Registrar data e horário automaticamente no servidor.

Assim cada compartilhamento cria uma nova ramificação rastreável.

12. SEGURANÇA E PRIVACIDADE
==================================================

O proprietário só pode rastrear arquivos que pertencem a ele.

Um destinatário não pode visualizar toda a base de clientes ou arquivos de outros criadores.

Não expor:

- service role key;
- secrets;
- dados privados;
- informações de outros usuários.

Todos os eventos críticos devem ser registrados no servidor, não apenas enviados pelo frontend.

Não confiar em nome, data/hora ou identidade enviados livremente pelo navegador.

A identidade de “quem compartilhou” deve ser determinada pela sessão/autenticação ou token seguro da entrega.

Data e horário devem ser gerados no servidor.
